## 文件系统

负责把块设备抽象为目录结构 可以创建修改查阅删除任意大小数据的结构 一系列数据块被抽象为一个文件

首先，需要使用数据结构 比如位图表示哪些块已经被使用 哪些块是空白块可以分配给文件

其次，需要数据结构储存所有文件的元信息和数据块映射信息 这就是FCB 文件控制块数据结构 但是为了加速寻找(因为我们只靠文件名字

寻找)，可以选择单独建立一个文件名到FCB的数据结构 叫做目录项，此时FCB就不需要存储文件名字了，相当于在sql中把一张表拆分为

两个表，通过FCB指针连接

最后，需要数据结构，用来记录文件系统的整体信息 超级块，因为世界上存在不同的文件系统，需要这个信息来判断你这个文件系统是

如何工作的

现代文件系统还会有日志，用来维护数据的一致性，使得断电出错的时候有容错能力，这几乎和数据库是一样的了

因为块设备本质上是外部设备，需要操作系统提供给应用程序使用，那么如何提供？答案是操作系统会建立一个打开文件实例数据结构，

用于维护当前所有打开的文件实例，相当于和块设备建立一个对话，每一个对话有一个整数索引，这个索引就是文件句柄，或者说文件描述符

而每个应用也会维护自己的打开文件数据结构

c++标准库封装了fd并添加了内存的一个缓冲期组成文件指针file*，只有在close的时候才会真正触发写的系统调用，这样可以合并多次读

## 分区盘

有分区表，把盘切成了多个区块。按分区表类型，有

### MBR 盘

1. LBA 0:       				MBR (主引导记录，含引导代码与4个主分区表项)

2. LBA 1 ~ 2047: 		隐藏扇区 / 引导间隙 (Bootloader 第二阶段代码或 1MB 对齐留白)

3. LBA 2048 ~ X: 		主分区 1 (包含 VBR 卷引导记录与文件系统数据)

4. ...: 							其他主分区 (主分区 2、3、4)

5. LBA Y ~ Z:   			扩展分区容器 (Extended Partition，用于突破4分区限制)
                					├─ EBR (扩展引导记录，链表指针)
                                					├─ 逻辑分区 (包含 VBR 与文件系统数据)
                                					└─ 下一个 EBR ...

6. LBA 末尾:    			厂商保留区 (如 HPA 主机保护区域 / DCO 设备配置覆盖，可选)




### GPT 盘



1. LBA 0:       			 保护性 MBR (Protective MBR)

2. LBA 1:      		 	 主 GPT 头 (Primary GPT Header)

3. LBA 2 ~ 33:  		 主分区表数组 (Primary Partition Entries)

4. LBA 34 ~ N-34: 	用户数据区 (真正存放文件系统的地方)

5. LBA N-33 ~ N-2:   备份分区表数组 (Backup Partition Entries)

6. LBA N-1:     		  备份 GPT 头 (Backup GPT Header)




### 其他

还有其他操作系统做的分区盘，如

- APM 盘 (Apple)

- BSD disklabel 盘

- Sun VTOC/SMI 盘




### 分区内容

分区里面的内容可以是：

**文件系统分区** ：提供文件抽象，存储各个文件

**交换分区** ：给操作系统当虚拟内存

**成员分区** ：加入 RAID/LVM 等

**加密分区** ：套了 LUKS/BitLocker

**启动/恢复/保留分区**： EFI、Recovery 等

### 作为文件系统盘

#### FAT

全称File Allocation Table文件配置表。为MS DOS系列操作系统使用，因为简单成为了软盘和存储卡的理想文件系统。

##### FAT12

1. 引导扇区 / VBR / BPB
2. 保留扇区
3. FAT1 表
4. FAT2 表（可选，通常有）
5. 固定根目录区
6. 数据区，从簇 2 开始
7. 尾部剩余扇区（若存在）

##### FAT16

1. 引导扇区 / VBR / BPB
2. 保留扇区
3. FAT1 表
4. FAT2 表（可选，通常有）
5. 固定根目录区
6. 数据区，从簇 2 开始
7. 尾部剩余扇区（若存在）

##### FAT32

1. 引导扇区 / VBR / BPB
2. 保留扇区，逻辑上包含 FSInfo、备份引导扇区等
3. FAT1 表
4. FAT2 表（可选，通常有）
5. 数据区，从簇 2 开始
6. 根目录在数据区内，是普通簇链，不是固定根目录区
7. 尾部剩余扇区（若存在）

簇 0、簇 1 只在 FAT 表里有保留表项，在数据区没有对应簇，不能存数据。数据区第一个可分配簇是簇 2。

FAT表...





#### exFAT

解决 FAT32 单文件 4GB 限制，大容量移动存储常用



#### NTFS

全称New Technology File System 新技术文件系统。是Windows NT 系列操作系统的默认磁盘格式。

现代 Windows (Win 7 / 8 / 10 / 11)
*(以标准 4KB 簇为例，1簇=8扇区)*

1. LBA 0 ~ 15：$Boot (VBR)
   固定占用最开始的 16 个扇区（8KB），包含引导代码和 BPB 参数。

2. LBA 16 起：$MFTMirr (MFT镜像)
   紧跟在 VBR 之后，存放主文件表前 4 个核心记录的备份。

3. $LogFile (事务日志)
   存放文件系统日志数据。

4. 其他元数据文件 ($Volume, $Bitmap 等)

5. 元数据之后 ~ 卷尾：普通数据区 (Data Area)
   这里是普通用户文件、大文件非驻留数据的存放地。
   *(注：系统会在这段数据区的前端划出一个逻辑上的 **MFT Zone**（通常占12.5%），禁止普通文件写入，专门留给 $MFT 扩展用，直到磁盘快满时才放开。)*

6. LCN 0xC0000 处 (约偏移 3GB 处)：$MFT (主文件表)
   现代系统故意将 MFT 作为一个巨型文件，放置在数据区深处（距卷首约 3GB 的位置），防止卷首频繁读写导致 MFT 碎片化。

7. 卷的绝对末尾 (最后 1 个 LBA)：Backup Boot Sector
   强制占用最后 1 个扇区，存放 VBR 的 512 字节完整备份。

早期 Windows (Win XP / Vista / 2000)

1. LBA 0 ~ 15：$Boot (VBR)
   固定占用最开始的 16 个扇区。
2. LBA 16 起：$MFT (主文件表)
   早期版本直接将 MFT 紧挨着 VBR 放置，导致卷首空间极易碎片化。
3. 紧随其后 ~ 卷中心点之前：普通数据区 (Data Area)
   存放普通用户文件数据。
4. 卷的物理中心点附近：$MFTMirr (MFT镜像) 与 $LogFile (事务日志)
   早期系统强制将镜像和日志放在磁盘正中心，为了平衡机械硬盘的磁头寻道时间。
5. 中心点之后 ~ 倒数第二个 LBA：普通数据区 (Data Area)
   数据区继续向后延伸，存放剩余文件数据。
6. 卷的绝对末尾 (最后 1 个 LBA)：Backup Boot Sector
   强制占用最后 1 个扇区，存放 VBR 的完整备份。
