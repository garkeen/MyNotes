线性时间选择第n大的元素

中位数的中位数

我们可以先问 求一组长度为n的数据的中位数需要多少时间复杂度？

假设是递归实现 为O (f n) f 0 1 2 3是常数

n个元素 分为k组 每一组选择中间数的时间为O(f n/k) 总共k*O(f n/k)

选择中间数的中间数T 时间为O(f k)

-A- -B- -C- -D- -T- -E- -F- -G- -H-

那么至少有1/4的数比T小 1/4的数比T大

注意我们不能直接抛弃比T小的1/4和比T大的1/4

那么接下来就只能是用T来分割数据 那么分割点必在中间的1/2

XXXXXXXXXXXXXXXXXTXXXXXXXX

此时极端情况下分割为1/4 3/4 中位数在剩下的3/4里

那么接下来怎么办 我们需要返回准确的中位数 此时我们只有分割后的T 无法确切的知道中位数到底在哪里

但是我们可以知道中位数在哪一侧 在那一侧继续找中位数的中位数T 继续分割 判断中位数在T的哪一侧

于是在此循环（不是递归！） 最终得到中位数
$$
f n	=[ k * f n/k+ f k + n ] * (1+ 3/4 + 3/4^2 + ...)
\newline
=4 * k *  f n/k + 4 * f k + 4 * n
$$
如果k是常数 那么

f x		=	C1 f(x/C2) + C3 x + C4

根据主定理 C1>C2 可以知道f x是幂函数

如果k不是常数 与n成正比怎么样？假设k=n/q

f n		=	[q n * f q+ f 1/q * n + n ] * (1+ 3/4 + 3/4^2 + ...)

​			 =	4 f n/q + 4n * (q f q + 1)

f x		 =	4 f x/C1 + C2 x

根据主定理 如果q=C1>4 那么f x是线性函数

因此如果我们按5个5个为一组 使用中位数的中位数思想递归找中位数 需要的时间复杂度是线性的
