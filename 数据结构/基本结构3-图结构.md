## 图 

$G=\{V,E\}$

由顶点集V和边集E组成

一个显然的事实是，在E出现过的点必须属于V 但是在V出现过的点不一定在E出现

|V|是图的顶点个数 也是**图的阶**





**简单图和重图**

简单图没有自指边 没有重边（同一个方向多条边）

我们一般只研究简单图。



**加权图**

如果边上有权重，那么这就是一个加权图 一般把加权图叫做**网**



**零图，平凡图和完全图**

一个简单图，如果没有顶点，就是**空图**；如果可以有顶点，但是没有边，那么就是**零图**

只有一个顶点的图就是**平凡图**，也可以说是**1阶零图**；

如果任意两个顶点都存在边，那么就是**完全图**



### 子图和补图

如果$G=\{V,E\}$而且$V' \in V,E' \in E$，那么$G'=\{V',E'\}$是G的**子图**

注意并不是随便的$V' \in V,E' \in E$都可以组成一个G，因为成图的要求是在E出现过的点必须属于V

如果G的子图G'的点集V'就是V 也就是**保留了全部点** 那么G’就是**生成子图**

如果G的子图G'的边集E'包含了在G中顶点集V‘涉及到的所有边  那么G'就是G由顶点集V'导出的子图 即**诱导子图/导出子图**



对于顶点集V 生成的完全图G(V,E) 任何顶点集是V的图G'(V,E')都必须是完全图G的子图

自然可以定义G-G'=(V,E-E')是G'的的**补图**





### 方向

根据图是否有方向分为无向图 和 有向图

**无向图**的边集由无向边$\{ (a_i,a_j\}$组成  

**有向图**的边集由有向边$\{ \langle a_i,a_j \rangle\}$组成 有向图中的有向边也叫**弧arc**

如果一个有向图没有环，那么这就是一个**有向无环图** （Directed Acyclic Graph DAG）

对于一个有向图 把里面所有方向反向 就得到了它的**转置图**



### 路

**游走**walk 

是一个有向的边序列 其中要求

无向图：后面的边和前面的边存在交点

有向图：后面边的开头是前面边的结尾

游走存在**起点**和**终点**

起点和终点相同的路径叫**闭途径**





**路径**path

除了起点和终点可以相同外 路径内**所有点都只出现一次**

起点和终点相同的路径叫**环**

显然 如果一个游走不是路径 那么其中一定存在一个闭途径



有教材把游走定义为路径 路径定义为简单路径 环定义为简单回路



**迹**

顶点可以重复 但是边不重复的游走

起点和终点相同的迹叫**闭迹**



一个无向连通图内所有的闭迹都可以由一个生成树+环基来表达





### 连通

如果一个图的两个顶点A和B存在路径，那么A和B连通

一个图并非任意两个点都连通（这在树是不同的，多个树放在一起被称为森林，而多个图放在一起看还是一个图）



**连通图和强连通图**

如果一个无向图任意两个点都有路径，那么这就是一个**连通图**；

如果一个有向图任意两个点都有路径，那么这就是一个**强连通图**；

如果一个有向图的基图任意两个点都有路径，那么这就是一个**弱连通图**；



**连通子图和极大连通子图** 

如果G的子图S是连通图，那么S就是G的连通子图



如果G'是G的一个连通子图 而且G不存在更大的连通子图S真包含这个连通子图G' 那么G'就是一个**极大连通子图**

显然极大连通子图必定是一个诱导子图



无向图的极大连通子图被称为G的**连通分量** Connected Component

所有CC的和恰好组成原来的无向图



有向图的极大连通子图被称为G的**强连通分量** Strongly Connected Component

所有SCC的和无法组成原来的有向图 因为**SCC之间还有边** 那么原来的有向图一定可以看成由这些**SCC连接得到的DAG**

这就是所谓的缩点DAG





**割点和割边**

无向连通图中，如果去掉某个点 不再连通 ->割点 如果去掉某个边 不再连通 ->割边





**生成树与生成森林**

对于无向图 包含所有顶点的**极小连通子图**就是它的**生成树**  有生成树当且仅当是连通图

如果图不连通 那么对每个连通分量求生成树 ，这些生成树组成的森林叫**生成森林**

显然 生成森林中**树的个数**就是**连通分量的个数**



对于有向图 如果存在包含所有顶点的有向树 那么这就是它的生成树 

然而包含所有顶点的有向树不一定存在 所以更好的办法是对每个SCC求一个子树 

然后这些子树不一定就是原图的生成森林 因为缩点DAG还有边可以合并这些树

那么缩点DAG如何贡献？因为这是一个DAG，它的生成树的个数至少是DAG源的个数

所以有向图的**生成森林**的**树的最少个数是缩点DAG源的个数**

有向图有**生成树**当且仅当**缩点DAG源的个数是1**



### 顶点的度

无向图的一个边给两个端点各自贡献一个度 所以
$$
\sum deg(V)=2|E|
$$
有向图的一个边给起点贡献一个**出度**，给终点贡献一个**入度**



如果无向图的每个顶点的度相同 那么这是一个无向的**正则图**

如果有向图的每个顶点的出度和入度相同 那么这是一个有向的**正则图**



### 存储方式

#### 顺序存储

一般默认有最大V和最大E 动态的需要特别处理

##### 边集数组

```C
typedef struct {
    int u, v;                 // 边的两个端点（顶点编号）
    //int w;                  // 权值，无权图可去掉
} Edge;

ElemType data[MAXV];          // 顶点表：下标即顶点编号
Edge     edges[MAXE];         // 边集数组

```

插入点O(1) 

插入边O(1) 需要查重就得O(E) 

查询边O(E)  

查询所有邻居O(E)

删除点O(E) 

删除边O(E)



##### 邻接矩阵

用一个$|V| \times |V|$的二维矩阵，对应位置是边的个数

对于带权重的图 对应位置写权重 一般使用$\infty$或者INT_MAX来描述没有边

```C
typedef struct {
    ElemType data[MAXV];        // 顶点表：下标即顶点编号，存顶点数据
    int      arcs[MAXV][MAXV];  // 邻接矩阵
} Graph;
```

插入点O(V) 

插入边O(1)

查询边O(1) 

查询所有邻居O(V)

删除点O(V) （删除所在行列 然后把最后一个元素的行列迁移过去）

删除边O(1)





对于无向图 矩阵一定是对称矩阵  对于有向图 就不一定了

对于简单图 对角线肯定都是0

显然矩阵顺序确定的话 图的邻接矩阵是固定的





#### 链式存储

##### 邻接表

使用 顶点表 存储顶点及其对应的边表的头指针  

使用 边表 存储某个顶点连接的邻边顶点 边节点数据是数组下标 因为点的地址是数组下标

```C
struct EdgeNode {
    int adjvex;              // 目标顶点在顶点数组中的下标
    struct EdgeNode *next;
};

struct VNode {
    ElemType data;
    struct EdgeNode *first;  // 该顶点的邻接表头指针
};

struct VNode verts[MAXV];    // 直接就是顶点数组
int n;                       // 顶点数
```



如果图的点需要扩展 那更好的方法是使用链表存储顶点及其对应的边表的头指针 

此时边表的边节点的数据是指针 不再是数组下标

```C
struct VNode;

struct EdgeNode {
    struct VNode *adjvex;    // 目标顶点指针
    struct EdgeNode *next;
};

struct VNode {
    ElemType data;
    struct EdgeNode *first;  // 邻接表头指针
    struct VNode *next;      // 下一个顶点
};

struct VNode *head;          // 顶点链表头指针
```

插入点O(1) 

插入边 使用头插法O(1)  如果要查重就需要O(deg(v))

查询边O(deg(v)) 

查询所有邻居O(deg(v))

删除点O(Σdeg(v)) 

删除边O(deg(v))



值得注意的是，即使顶点数组顺序确定的 边表内部顺序也可以是乱的 所以一个图固定数组顺序 邻接表也不是唯一的

可以想象为边表内部元素按照顺序排列 然后可以用一条允许重叠的线串起来



**反邻接表** 

对于有向图 邻接表的顶点表默认是按从该顶点出发的边

这样计算顶点的出度简单 但是入度难 所以有**反邻接表**   顶点表保存到该顶点的边 



##### 邻接多重表

对于无向图  每个边都要存储两次 改进就是 邻接多重表 每个边只会存储一次 边节点同时存储它在左右两顶点的next指针

```C
struct EdgeNode {
    int            ivex, jvex;   // 边的两个端点
    struct EdgeNode *ilink;      // 依附 ivex 的下一条边
    struct EdgeNode *jlink;      // 依附 jvex 的下一条边
} EdgeNode;

struct VNode{
    ElemType  data;              // 顶点数据
    EdgeNode *firstedge;         // 第一条依附的边
};


struct VNode verts[MAXV];
```

这里需要注意，遍历某个顶点V的边表的时候，每遇到一个EdgeNode都必须判定**到底ivex和jvex哪个是V**，而不是固定的找第一个或者第二个！这和后面的十字链表不一样，由于有向，顺序肯定确定了。



##### 十字链表

对于有向图 邻接表计算顶点的出度简单 入度难 反邻接表计算顶点的出度难  入度简单

本质上是因为邻接表只维护出边 反邻接表只维护入边

综合两种方法得到 十字链表 也就是**一个顶点同时维护它入边和出边** 每个边依然只存储一次 边节点同时存储它在作为in和out的next指针

```C
struct ArcNode {
    int             tailvex, headvex;  // 弧尾、弧头顶点编号
    struct ArcNode *tlink;             // 弧尾相同 作为入边表的下一条弧
    struct ArcNode *hlink;             // 弧头相同 作为出边表的下一条弧
} ArcNode;

struct VNode {
    ElemType  data;
    ArcNode  *firstin;                 // 入边表头（弧头是本站的弧）
    ArcNode  *firstout;                // 出边表头（弧尾是本站的弧）
} VNode;


struct VexNode verts[MAXV];

```

显然这种情况下是不需要判定顶点是左还是右 因为表强制分为了入边表和出边表

顶点的入边是进入到这个顶点的边

顶点的出边是从这个顶点出来的边

### 图的遍历

需要指定一个顶点当源头顶点

由于图可能有回路 必须维护一个**visit表**来标记哪些被访问过 无论是DFS还是BFS都是如此

又由于图可能不连通 所有全图的完整遍历 需要从visit的表中选择没有访问的继续做源头顶点 进行**多次遍历**

每次从某个点出发遍历 又不会碰到已经访问的顶点 一次遍历得到的完整遍历路径一定是树 而树的根就是源头顶点

1. 对于无向图：从某个点出发遍历可以到达的所有顶点就是自己**所在连通分量**的全部顶点

   因此其遍历得到的树就是所在连通分量的生成树

2. 对于有向图：从某个点出发遍历可以到达的所有顶点除了自己**所在强连通分量**的全部顶点 加上缩点DAG后续的所有顶点

   

**深度优先遍历**

```C
void DFS(Graph *g, int v) {
    visited[v] = 1;
    Visit(g, v);

    for (int w = FirstAdjVex(g, v); w != -1; w = NextAdjVex(g, v, w)) {
        if (!visited[w]) {
            parent[w] = v;      /* 生成树边 v -> w */
            DFS(g, w);
        }
    }
}
```



**广度优先遍历**

```C
void BFS(Graph *g, int s) {
    QInit();

    visited[s] = 1;
    Visit(g, s);
    QPush(s);

    while (!QEmpty()) {
        int u = QPop();
        for (int w = FirstAdjVex(g, u); w != -1; w = NextAdjVex(g, u, w)) {
            if (!visited[w]) {
                visited[w] = 1;    /* 关键：入队时就标记 */
                parent[w]  = u;
                Visit(g, w);
                QPush(w);
            }
        }
    }
}
```
