## 函数的组合Composition

比如我们想定义

h(x)=f(g(x))

但是懒得写括号，那么更优雅的方法

h = f.g

(.) :: (b->c) -> (a->b) -> a -> c



当遇到f g h x和f.g.h x y.z这种形式的项，就要想

同一个操作符到底是左结合还是右结合？

空格和.的优先级到底是什么？

注意，Haskell和Ocaml等函数式语言，空格（也就是函数应用）是左结合的，也就是说

f g h x=> f1 h x=>f2 x

其中f1 = f g f2 = f1 h

或者看成 ((f g) h) x

但是.是右结合的，所以

f.g.h=f.(g.h)

函数应用运算符高于所有中缀运算符，所以

f.g.h x y.z=f.g.((h x) y).z=f.(g.((h x) y ).z) )

这里一定要区分f.g和f g的区别

f g x就是 （f g) x,其中g是f的输入，输出的结果f(g)是一个函数 这个函数的输入类型必须和x一样

f.g x就是 f(g(x)) 但是f.g由于可以单独成函数，所以f.g的输入类型必须是g的输入类型 输出类型必须是f的输出类型

f.g并不是 f g，一定要注意！！！！

同样的， f.g x和(f.g) x也不是一个东西！ f.g x本质上是f.(g x) 其中(g x)是一个函数，而 (f.g) x等价于 f (g x)



现在我们实践一下，map2d=map.map

那么，这到底是什么东西？我们可以通过类型推断得到

map2d::(a->b)->[[a]]->[[b]]

可以猜到是把二阶列表里的所有a变成b=f(a)，但是我们还是不知道这到底是如何工作的，

类型推断只告诉我们类型，没有告诉我们实现，万一不是这样的呢？关键在于我们需要知道**部分应用的结果**到底是什么

map2d f list

=(map.map) f list

=map(map(f)) list

map(f)是个啥？是一个函数，输入一个列表，输出一个列表，所以

map(map(f)) list就是把map(f)这个函数逐个应用到list的各个元素里面

下次看到(map.map) f list 而且只通过类型推断猜到要干嘛，但还是感觉不靠谱，就写成

map(map(f)) list这就十分清楚了

### Folding折叠

foldr :: (a->b->b) -> b -> [a] -> b

foldr ⊕ init [x1,x2,x3,...] => (x1⊕(x2⊕(x3⊕...(xn⊕init))))

相当于Reduce

sum = foldr (+) 0

or = foldr (||) False

and = foldr (&&) True

foldr::(\elem acc -> <term>) <start_acc> <list>



map f = foldr (  (:) . f  ) []
