### 定义相等

完全相同的两个类型被认为是定义相等的，例如 `Nat` 和 `Nat` 或 `List String` 和 `List String`。 任何两个由不同数据类型构造的具体类型都不相等，因此 `List Nat` 不等于 `Int`。 此外，两个只在内部名称上存在不同的类型（译者注：即α-等价）是相等的，例如 `(n : Nat) → Vect String n` 与 `(k : Nat) → Vect String k`

然而，类型不仅包含函数类型、数据类型和构造子。 它们还包含*变量*和*函数*。 变量的定义相等性相对简单：每个变量只等于自己，因此 `(n k : Nat) → Vect Int n` 不等于 `(n k : Nat) → Vect Int k`。 函数则复杂得多。数学上对函数相等的定义为两个函数具有相同的输入输出行为。但这种相等性无法被算法检查。 这违背了而定义相等性的目的：通过算法自动检查两个类型是否相等。 因此，Lean 认为函数只有在它们的函数体定义相等时才是定义相等的。 换句话说，两个函数必须使用*相同的算法*，调用*相同的辅助函数*，才能被认为是定义相等的。 这通常不是很有用，因此函数的定义相等一般只用于当两个类型中出现完全相同的函数时。

### 命题相等

考虑实现一个加法函数，

0 + k = k

succ a + k = a + succ k

那么进行定义相等时 我们有

0+1 = 1+0

3+2 = 2+3 = 5
但是，如果值是抽象变量呢 比如

0 + k ?= k + 0 ？=k

我们知道对于任意k都成立 但是这不是显然的 由于k不知道 无法进行规约

因为你不知道k+0 你就算得到 (k-1) + 1然后呢 继续规约？ 你不知道k-1是不是0 你也不知道要规约多久才会停机

因此这就涉及到我们需要证明

0 + k ?= k + 0 ？=k

这就是命题相等

我们需要一个函数实现

a->b->add(a,b)->add(b,a)

### 构造器与类型的区别
```
inductive Nat where 
| zero : Nat 
| succ (n : Nat) : Nat
```
其中，zero和succ被称为构造器，构造器不是类型



理论上，C# Java C++可以基于面向对象的父子类做类似的实现

```
abstract class Nat {}
class Zero : Nat {}
class Succ : Nat {
    public Nat n;
    public Succ(Nat pred) {
        n = pred;
    }
}
```

其中，父子类的关系用于模拟和类型

但问题是，Succ和Zero也是类型，而不单是构造器

## 多态类型

```
structure PPoint (α : Type) where  
x : α  
y : α
```

PPoint可以看成是类型构造器 PPoint int才是完整类型

函数上的多态

```
def replaceX (α : Type) (point : PPoint α) (newX : α) : PPoint α :=  
{ point with x := newX }
```

这叫**显式参数绑定**，可以看作replaceX部分应用α才是一个拥有完整信息的函数

在 Lean 中，依赖类型函数的参数**必须按照依赖顺序书写**：一个参数的类型可以依赖于之前定义的参数，但不能依赖于之后定义的

```
#check (replaceX)
replaceX : (α : Type) → PPoint α → α → PPoint α
```

这看起来很蠢，因为理论上我提供的point和newX就有α了，我居然还要再输入α

所以后面会有**隐式参数绑定**



多态分为参数多态，特设多态和子类型多态

参数多态就是systemF

特设多态就是函数重载

子类型多态就是父子类关系

## 类型层面的模式匹配

在lean，你可以在类型注解中使用函数，这意味着你可以写出这种代码

-- 定义一个函数，返回类型取决于输入的值
def tupleType (n : Nat) : Type :=
  match n with
  | 0 => Unit      -- 空元组
  | 1 => Int       -- 单个整数
  | 2 => Int × Int -- 整数对
  | _ => List Int  -- 其他情况返回整数列表

-- 使用：根据输入值，返回不同类型的值
def mkTuple (n : Nat) : tupleType n :=
  match n with
  | 0 => ()
  | 1 => 42
  | 2 => (42, 24)
  | _ => [1, 2, 3, 4, 5]
