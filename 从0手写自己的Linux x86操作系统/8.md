### 创建子进程 fork

任务需要指向一个父进程pid

子进程结束后，父进程必须用 `wait()` 或 `waitpid()` 回收其 PCB 资源，否则子进程会变成僵尸进程

父进程先退出时，子进程会被 PID 为 1 的 `init`/`systemd` 进程接管，自动完成资源回收



fork申请失败返回-1

申请成功 对于父进程 返回子进程pid 对于子进程 返回0



fork的实现本质是初始化新进程并添加进程到就绪列表 

这个进程TSS全部都复制父母进程 除了eax设置为0（fork返回值）

还有一个就是子进程的各个段都需要复制 

具体操作是通过扫描父进程的页表 然后只要不是系统空间的（因为有共享）都申请新页然后复制

还有一个就是子进程的打开文件表（后面会讲）都需要复制 

还有就是父进程从fork是通过中断返回 而子进程不需要被返回 所以EIP不能无脑复制 需要添加



### 创建新进程 exec

这非常重要 我们终于可以从文件中启动进程了 我们就假设使用elf文件启动 

（这里涉及到磁盘的读取 后面会讲）

elf对象有一个entry point address 

执行的第一条指令就是从这地址开始

然后会初始化C运行环境 再调用main函数



用户程序A执行exec启动程序B本质是把自己的状态覆盖掉 也就是说exec会覆盖 B的pid就是A的pid

因此 进程A使用exec启动一个进程B 进程B结束会不会返回到进程A 因为这是覆盖不是创建新的

因此 如果我想要exec启动程序 但是自己还想要继续运行 必须先fork再exec

因此 exex需要把程序A的各个物理页都释放 因为不可能再使用了

然后需要从磁盘解析elf头 把段按页读取 加载到内存 设置页表

注意 .bss .text .data的虚拟地址就按elf来 物理地址动态生成 （由于是平坦模型 不需要关注指令到底访问的是什么段 全部段基址都是0）

除了搬运之外 还需要主动申请空的栈空间和堆空间



完成搬运和申请栈 堆后 需要修改当前栈顶的返回地址为entry point address  这样借助中断返回机制直接跳到elf的入口地址



由于exec有参数给main 需要拷贝
