### 从SISD到SIMD

```c++
for(int i=0;i<n;i++)
{
    c[i]=a[i]+b[i];
}
```

为了执行n长向量的加法，需要执行n个加法和访存的指令周期，但是注意访存有很痛苦的延迟代价。

由于访存是连续的，因此虽然我们可以多次命中Cache，但是从cache到ALU依然浪费很多时间；

即使我们可以并行，但我们没有这么多ALU；

为什么我们在不能在硬件上，一次性取出A B向量的所有值，然后做一个专门的，N长的ALU单元，得到C向量，然后一次性写回？

（实际上，我们不会造出一个巨大的、能同时操作N个数的单片ALU，而是用N个更小的、并排排列的ALU“通道”（Lanes）组成）

这样，我们只要一次性访存，一次性计算和写回，只需要1个加法和访存的指令周期，速度提升n倍！

```c++
V_ADD(c,a,b)
```

我们专门做了一个硬件，使得A B向量的数据可以一次性读入，通过n个操作数长的数据通路导引到专门的n长的ALU单元进行计算

但是，如果有分支怎么办？
```c++
for(int i=0;i<n;i++)
{
    if(i%2==0)
    {
        c[i]=a[i]+b[i];
    }
    else
    {
        c[i]=a[i]-b[i];
    }
}
```

如果我们使用

```c++
V_ADD(c,a,b)
```

就会得到一些值是错误的，因此，我们需要设计一种操作把错误的结果变成0

```c++
V_MOD(mask,mask,2)
//设计一个专门的硬件计算哪些值是正确的 这就是掩码
V_ADD(c,a,b)
V_MUL(c,c,mask)

V_SUB(mask1,1,mask1)
//假设用一个全1的向量减去mask1 得到其掩码的反
V_SUB(e,a,b)
V_MUL(e,e,mask)

V_ADD(c,c,e)
//将两个正确的的结果相加
```

这种掩码实现其实是很低效的，如果我们能在硬件上实现掩码就好了

### 如何从SIMD到SIMT

我们决定在硬件上实现掩码，这样就不需要显式的写代码合并正确结果，而是交给硬件根据if生成掩码

那么这个强大的硬件需要：

**根据代码自动识别分支**

编译期生成控制流图，并标记分支结构和合流点

**自动生成掩码**

硬件根据编译器的信息辅助，在恰当时刻生成掩码并管理控制流

**自动合并结果**

在分支结束后，硬件实现数据流的合并，使得这些数据流依然是同指令执行

这意味着我们需要保存每个数据流的数据状态，以及当前的执行路径，这几乎和一个线程是相同的了！

因此，SIMT的想法出现了：我们不再把代码逻辑看成是单个很宽的数据流，而是直接看成许多独立的数据流，就像看待线程一样；只不过，如果这些线程访问的数据是连续的，那么就可以自动合并为一次访问，一次计算，一次写回。

如果多个数据流之后的路径都不同，怎么办？这就是SIMT和MIMD的关键区别：

- SIMT宁愿在同一个 SIMD 执行单元上，按照线程掩码，多次**串行**地执行不同的路径；
- MIMD可以每次并行的使用多个计算单元计算每一个数据流，无需串行

但是我们知道，MIMD实现起来耗费太高，实际中可能有上千/上万个线程，这意味着我们对每个数据流都要有单独的调度器，这种代价是正常人不可承受的！因此，SIMT对32个线程作为一个原子的调度单位warp，而不是MIMD每个线程都是单独的调度单位。这种结果就是SIMT的调度单元相比于MIMD大大减少了

因此，我们

创造专门的硬件，保存每个线程的状态；

再来一个硬件处理连续/不连续的内存访问，自动合并成一个向量发送给执行单元；

再来一个硬件储存掩码栈用来处理分支的数据流

我们就大概实现了一个SM了，不过我们还有优化的地方：

由于一个调度单元可以管理多个warp，一旦某个warp因为内存访问延迟了，我们就可以像操作系统一样自动换一个空闲的可以立即执行的warp隐藏这种访问延迟带来的损耗
